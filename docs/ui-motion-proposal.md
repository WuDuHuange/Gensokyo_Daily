## 一、诊断：死气的根因不是「缺动画」

先把现有动效盘了一遍（`js/motion.js` + `css/input.css`），一共 14 项：

| # | 动效 | 触发时机 | 类型 |
|---|---|---|---|
| 1 | 加载遮罩「报纸拆封」`sheet-unfold` | 首屏 | **一次性** |
| 2 | 报头装饰线展开 `transform .9s` | 首屏 | **一次性** |
| 3 | 刊名墨迹落定 `ink-in--masthead`（含字距收拢） | 首屏 | **一次性** |
| 4 | 卡片墨迹浮现 `ink-in` | 首屏 | **一次性** |
| 5 | `[data-reveal]` 错峰入场（45ms 步长，上限 300ms） | 滚动 | **一次性** |
| 6 | 图片淡入 `img-fade` | 滚动 | **一次性** |
| 7 | 副刊卡悬停：转正 + 放大 1.045 + 抬起 4px + 阴影 | 悬停 | 交互 |
| 8 | 广告卡悬停 | 悬停 | 交互 |
| 9 | 标题下划线「高亮笔」`background-size 0→100%` | 悬停 | 交互 |
| 10 | 工具坞圆钮 / 菜单开合 | 点击 | 交互 |
| 11 | 主题切换：全站颜色 460ms 交叉淡入 | 点击 | 交互 |
| 12 | 回到报头平滑滚动 | 点击 | 交互 |
| 13 | 天气图标：日转 / 雨移 / 闪 / 雪摆 / 云呼吸 / 异变脉冲 | **常驻** | 环境 |
| 14 | 滚动进度条 `scaleX` | **常驻** | 环境 |

**14 项里，13 项是"演一次就结束"。常驻的只有第 13、14 项。**

所以真实情况是：**页面打开后演大约 1.5 秒，然后彻底静止。**
不是没有动效 —— 是动效全挤在入场那一瞬，之后整页是一张静止的图。

而**配色本身没错**。墨 + 朱是一套印刷色板，它天然是"平"的：只有明度对比、没有色相变化。
静止时它读起来就是"印好的纸"。这不是缺陷，是这套色板的本性 ——
**要让印刷色板活起来，靠的不是给它加颜色，是让"墨"和"光"动起来。**

## 二、参照系：iOS 与鸿蒙，具体拿什么

### iOS 拿五条

1. **`:active` 必须即时，`:hover` 可以慢。** 按下反馈延迟超过 ~100ms 就会觉得"钝"。
   现在 `.tool-fab` 的 `:active` 是 220ms —— 偏慢，会显得黏。
2. **可打断（interruptible）。** 动画不锁交互：播到一半改主意，能立刻接手，不回跳。
3. **空间一致性。** 元素从它来的方向进出（sheet 从下往上，就从下往上回去）。
4. **克制（deference）。** 动效永远不抢内容的戏。这是"不花哨"的原始定义。
5. **Reduce Motion 不是"不动"，是"换一种动法"** —— 用交叉淡入替代位移。

### 鸿蒙拿五条

1. **一次点击、一步直达。** 不做多余的中间态（所以不做 loading 骨架屏、不做多段弹跳）。
2. **物理动效。** 弹性 / 惯性 / 阻尼 / 摩擦 —— 用物理参数而不是固定时长曲线。
3. **无缝转场（一镜到底）。** 元素从 A 位置"长"到 B 位置，而不是 A 消失、B 出现。
4. **呼吸感。** 有机节奏，不用机械的 linear。
5. **跟手。** 反馈紧贴输入，不许有延迟。

### 两者共同的、我们要照搬的

- 动效服务于**因果**（我做了什么 → 它怎么回应），不服务于**装饰**
- 时长普遍短：交互 90–320ms，只有"点亮 / 转场"类才到 400ms+
- 缓动以「快出慢收」为主，**避免 linear，避免大幅过冲**

### 两者都不做、我们也不做的

- 常驻的装饰性动画（这正是"花哨"的来源）
- 大幅位移、3D 翻转
- 彩色光效、粒子、渐变扫光

## 三、动效语汇：纸 · 墨 · 光

所有新动效必须能归入这三种材质，归不进去就不做。这条规则用来挡住"顺手加一个"。

| 材质 | 物理直觉 | 允许的效果 |
|---|---|---|
| **纸** | 有重量、有厚度、受光 | 抬起、落下、回弹、错峰 |
| **墨** | 会渗、会干、笔画有先后 | 书写、渗开、渐显 |
| **光** | 从某处来、有方向 | 点亮、明暗呼吸 |

**禁止**：粒子、光斑、3D 翻转、光标跟随、彩虹渐变、>8px 的位移视差。

## 四、清单

配比刻意做成 **交互 60% / 连贯 25% / 呼吸 15%** ——
因为 iOS 和鸿蒙的"活"主要来自响应，不来自常驻动画。

### A 档 · 交互响应（60%，最主要的一档）

| 编号 | 效果 | 现状 | 改法 | 时长 |
|---|---|---|---|---|
| **A1** | 标题下划线「书写」 | 已有，`.45s` 偏慢 | 收到 `.32s`，换 `--ease-draw` | 320ms |
| **A2** | **全站可点对象的按下反馈** | 只有工具坞有 | `.news-title-link` / `.brief-item` / `.art-card` / `.ad-card` 加 `:active { scale: .99 }` | **90ms** |
| **A3** | 卡片抬起物理化 | 已有，但用 `ease-ink`（落定曲线），抬起时像"被吸上去" | 换 `--ease-lift`，抬起 3px（不是 4px），阴影同步 | 220ms |
| **A4** | 来源标签微响应 | 无 | 悬停时下方 1px 朱色短线 `scaleX 0→1` | 140ms |
| **A5** | 区块头细线「书写」 | 无 | 进视口时 `scaleX 0→1`，随 `[data-reveal]` | 320ms |
| **A6** | 焦点环墨点扩散 | 只有默认 outline | outline 保留 + 一层 `box-shadow` 0→4px | 160ms |

> **A2 是这一档里性价比最高的一条。** 现在全站只有工具坞有按下反馈，
> 其余可点对象点了毫无触感 —— 这是"死气"最直接的来源。
> 注意 `:active` 的 90ms 必须显著短于 `:hover` 的 220–320ms，否则按下像延迟。

### B 档 · 空间连贯（25%）

| 编号 | 效果 | 现状 | 改法 | 风险 |
|---|---|---|---|---|
| **B1** | **日夜切换「点灯」转场** | 全站颜色 460ms 交叉淡入，没有方向感 | 从切换按钮位置发散径向遮罩（`clip-path: circle()` 0→150%），优先用 View Transitions API，不支持则回退现方案 | **中，最"花"的一条，可单独砍** |
| **B2** | 工具坞菜单项依次入场 | 整块一起出现 | 菜单项从圆钮方向依次弹出，每项延迟 28ms，收起时延迟倒序 | 低 |
| **B3** | 回到报头平滑滚动 | 已有 | 不动 | — |

### C 档 · 静止呼吸（15%，只放三处）

| 编号 | 效果 | 参数 | 说明 |
|---|---|---|---|
| **C1** | **纸的受光**（日间） | 对角光带，20s 周期横移，峰值不透明度 **≤2.5%** | 潜意识觉得"纸在动"，不该能明确看到光斑 |
| **C2** | **灯笼呼吸**（夜间） | 纸面色温 ±2% 明度，8s 周期 | 呼应「夜读 · 灯笼」的主题命名 |
| **C3** | **朱色的呼吸** | 夜间，朱色明度 ±3%，6s 周期 | **只作用于报头朱色元素与区块头短横线，不作用于正文里的朱色文字**（正文跳动会干扰阅读）。白天不做 —— 白纸上朱色跳动会显廉价 |

> ⚠️ **C 档最容易做过头，判定标准很硬：**
> 把页面静置 3 秒，**如果你能指出哪里在动，就是过了**。
> 三处呼吸都必须**在 `document.hidden` 时暂停**，并在滚动时降频。

### D 档 · 不做（明确写下来，免得以后手痒）

- 光标跟随 / 磁吸按钮
- 粒子、光斑、渐变扫光（>3% 不透明度）
- 3D 翻转、卡片跟随鼠标倾斜
- 自动轮播 / 自动滚动
- 大位移视差（>8px）
- 弹跳过头的卡通缓动（overshoot >8%）
- 数字滚动 / 打字机效果
- 骨架屏 shimmer

## 五、技术约定

**缓动令牌**（现有两个保留，新增两个）

```css
--ease-ink:   cubic-bezier(.16, 1, .3, 1);      /* 已有 · 落定，入场用 */
--ease-press: cubic-bezier(.34, 1.56, .64, 1);  /* 已有 · 回弹，按钮用 */
--ease-lift:  cubic-bezier(.2, .8, .2, 1);      /* 新增 · 抬起 / 位移 */
--ease-draw:  cubic-bezier(.65, 0, .35, 1);     /* 新增 · 书写 / 绘制 */
```

**时长档位**（不许自创）：`90 / 140 / 220 / 320 / 500 / 900 ms`

**硬约束**

- 只动 `transform` / `opacity` / `filter`，不碰 `width` / `height` / `top` / `left`
- 同时运行的动画上限 **6 个**
- 全部接进现有的 `prefers-reduced-motion` 降级块
- 常驻动效（C 档）必须在 `document.hidden` 时暂停
- **不引入任何动画库** —— 现有 CSS + 少量 JS 足够，引库会让首屏多一个请求
- C 档只加合成层属性，不新增 repaint

## 六、验收方式

1. **性能**：CDP 读 `document.getAnimations().length`、合成层数、帧耗时
2. **回归**：现有六套验证脚本（T0 / 结构 / 配色 / 图标 / 结构②+字体 / 工具坞窄屏）必须继续全过
3. **降级**：`prefers-reduced-motion: reduce` 下逐一确认新动效全部失效、页面完全可用
4. **目视**：日 / 夜各出一组「静置截图 vs 动效中截图」
5. **主观**：C 档用「静置 3 秒能否指出哪里在动」判花哨与否

| 步 | 内容 | 风险 | 可单独砍 |
